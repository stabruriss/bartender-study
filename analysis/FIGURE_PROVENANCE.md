# Reproducing and checking the numerical figures

Figures 4–7 are vector plots generated by Python and Matplotlib from the accepted
study-01 simulation aggregates. The rendering pipeline contains no generative
image model, image editing, hand-drawn data points, fitted trend replacement or
manual numerical corrections. Lines join the observed aggregate points unless
explicitly labeled as a first-order prediction or a fixed reference.

## From retained runs to the plotted numbers

1. The execution machine retained 29,700 successful seed/cell records for the
   approved 990-cell grid. Its approved `verify-02` revalidation passed and
   reported every original raw file unchanged against the first inventory.
2. The maintainer verified the transferred per-seed summary file's original
   hash and size, all cell/seed identities and scenarios, then independently
   reran the study's aggregation code. Both `summary.csv` and
   `paired-differences.csv` matched exactly, including field strings and row
   multiplicities. This is recorded in
   `validation/delivery-acceptance-m1.json`; the review code is
   `validation/review_delivery.py`.
3. The plotting reader pins the SHA-256 hashes of those two CSVs and the
   approved `cells.json`. Observed figure values come from `summary.csv`;
   paired comparison tables also preserve the supplied paired CSV. The grid
   supplies coordinates, policies and nominal theory parameters.
4. Immediately before vector export, `plot_provenance.py` reads the **actual
   Matplotlib line and error-bar coordinates**. `manuscript/plot-data.csv`
   records their figure, panel and axis index, displayed series, source cell,
   source metrics and component means/intervals/counts, formula, input hashes,
   actual x/y and interval endpoints, scales, line style and marker.
5. `verify_plot_data.py` reconstructs the complete expected point set directly
   from the accepted CSV/grid using a separate standard-library implementation.
   It imports neither the plotting generator nor the simulation code. It checks
   every coordinate, source association, panel, interval and line convention,
   exact coverage, source hashes, generating-code hashes and output hashes.

The audit covers **1,434 artist coordinates**: 195 observed aggregate points,
1,227 nominal-model coordinates, and 12 reference-line endpoints. Those last
two groups are explicitly identified and are not additional observations.
All 123 displayed source intervals are checked. Each mean retains its source
seed count; undefined seeds are handled by the accepted aggregation, not
silently replaced with zeros in the plot.

| Figure | Plotted observation | Calculation and scope |
|---|---|---|
| 4 | Repair starts and observed repair work | Original per-cell means and 95% normal intervals, both policies, five agent/dependency slices. Log axes change display scale only. |
| 5 | Overlap-pair rate, first-conflict rate, first-conflict overlap | Original per-cell means/intervals, relocation 0. Only overlap-pair rate is compared with C(n,2)pλ²τ. |
| 6 | Initial conflicts resolved by window end | `(completed repairs − failed completed repairs) / initial conflicts`, pooling counts from the same 30 seeds; zero dependency only. |
| 7 | Failed completed attempts | `failed completed repairs / completed repairs`, pooling the same 30 seeds. Nominal q is `1 − exp(−μE)`, using E=δ+R at dispatch and E≈R when re-reading. |

`manuscript/wait-reference.csv` retains the three component means, original
intervals and seed counts for all 36 waiting combinations. Ratio intervals
cannot be recovered from marginal aggregates without covariance; none are
invented. Completed attempts are selected by the serial queue and cutoff.

## What the solid line means in Figures 6 and 7

The waiting suite models kick-back with two baseline-read timings. Bartender
is represented by the immediate-dispatch operating point, δ=0, in that model.
Both read timings give the same value there. This is a simulation reference,
not an additional benchmark of the running application.

The solid line extends that observed zero-wait value across the comparator's
waiting axis for comparison. It does not claim that Bartender was scanned at
those waiting values. In `plot-data.csv`, its two endpoints both reference
the same zero-wait cell and use the `zero_wait_reference:` formula prefix.
The dashed curves are the two delayed comparators, and the thin dotted curves
in Figure 7 are nominal first-order predictions. Endpoint annotations are
rounded copies of the exact plotted values.

## Commands

From the repository root, use the analysis environment described in
`analysis/README.md` (CPython 3.12.4 and `analysis/requirements.lock`):

```sh
local-logs/analysis-venv/bin/python analysis/make_manuscript_figures.py
python3 analysis/verify_plot_data.py
python3 analysis/check_plot_verifier_failures.py
```

The verifier needs only the Python standard library. Its report is
`analysis/manuscript/plot-verification.json`. The failure checks alter only
temporary copies: a changed y value, wrong source cell, missing point,
duplicate point and incorrect baseline line style must all be rejected.
The copied manifest's plot-data hash is updated first, so those checks exercise
the source/coordinate verification rather than just a stale checksum.

For an independent fresh export without overwriting the supplied figures:

```sh
local-logs/analysis-venv/bin/python analysis/make_manuscript_figures.py --output-dir local-logs/figure-reproduction
python3 analysis/verify_plot_data.py --directory local-logs/figure-reproduction
```

`manuscript/manifest.json` binds the input, code and vector-output hashes.
Reproduction is expected to match the vector bytes with the recorded plotting
environment. Different font/rendering versions may alter PDF/SVG encoding;
the exported data coordinates remain separately checkable.

## Limits of the evidence

Hashes establish file identity, not model validity. The maintainer independently
checked the transferred per-seed summaries and aggregation; the full raw
run/flow archives remain on the execution machine. Their unchanged-file claim
comes from its approved revalidation, not a new local rehash of the archives.
The repository publishes the archive index and checksums. The retained raw
parts are not yet downloadable; they will be uploaded separately as release
attachments, with URLs recorded in `release/RAW_ARCHIVES.json`. Publication of
the source repository need not wait for those uploads. Until the parts are
available, a reader can reproduce the aggregate-to-figure checks but cannot
independently replay the full raw-history audit from public downloads.

These checks establish a reproducible correspondence between accepted
simulation observations and figures. They do not establish that the synthetic
model describes every real project, that a theoretical collision assumption
holds, or that model effort measures real application latency. Those remain
separate scientific questions. Original scans and negative results remain in
`analysis/results/`; no simulation was rerun for these display changes.
